# Cloche: art and asset plan

How Cloche gets from code-drawn placeholders to a premium, studio-quality look: what is made outside the app (Blender, audio, marketing), what stays in Swift, the oven-to-plating transition, and the order to build it in.

## Decisions so far (2026-11-01)

| Decision | Choice |
| --- | --- |
| Art direction | **Stylised realism**: real materials and light (porcelain, glass, brushed steel, crumb, glaze), slightly simplified shapes, a curated warm palette. Appetising, never uncanny. |
| Oven | Built in **Blender** from the owner's brief (2026-11-01): a **hyperreal** hero asset, generated by Python scripts in `scripts/blender/` (Claude builds, owner approves each of 5 stages). Matches `reference/oven_ref.png`. See "Oven build" below. |
| Other 3D assets | **Oven only for now**; the rest stay code-drawn placeholders until decided. |
| Oven to decorating | **One continuous shot** along a single counter (storyboard below). |
| How 3D reaches the app | **Leaning pre-rendered** for the oven: the brief asks for transparent PNG stills plus 48 door frames (any hinge angle maps to a frame), with an optional USDZ. Live 3D stays possible from the same `.blend`; the spike in Step 1 still settles it for the rest of the set. |

## The dividing rule

> **Make it outside the app if it has a fixed shape or look. Build it in code if it changes with the player, the clock, the device, or the language.**

- **Outside (Blender, audio, design tools):** objects, their materials and textures, the kitchen set, lighting environments, sound recordings, the app icon and marketing renders.
- **In code (Swift):** everything that moves because of game state (door, rack, glow, browning, steam, camera), everything the player creates (icing strokes, topping placement), all text, timers and buttons, per-device layout (iPhone, the Duo open, the Duo cover), accessibility, Reduce Motion, sound and haptic timing.

Why studios split it this way: assets are expensive to change and cheap to reuse, while code is cheap to change. A model with clean parts and named pivots can be opened, slid, lit and browned by code in endless combinations. A model with motion or text baked in has to be re-exported for every change.

## What you make outside the app

### A. 3D models (Blender)

Priority order. Items 1 to 3 unlock the transition; items 4 to 7 unlock decorating.

| # | Asset | Parts to keep as separate named objects | Notes |
| --- | --- | --- | --- |
| 1 | **Oven** (in progress) | Body, Door (pivot on the bottom hinge line), Door glass, Handle, Rack (pivot for sliding out), Top and bottom heating elements (emissive material), Display (a flat plane with UV 0 to 1, text drawn by code), 2 to 3 Knobs (pivot at each centre), Interior cavity, Tray or baking tin | No text or numbers on the model; code owns the display. Door glass must be a real transparent material so the dish shows through it. |
| 2 | **Kitchen counter set** | Counter top, Back wall or splashback, a few quiet props (flour jar, whisk, linen) | **Needed for the continuous shot:** one counter runs from the oven to the plating station, about 1.2 to 1.6 m long. Static, so its lighting can be baked into a texture (cheap and beautiful). |
| 3 | **Cake lifter** (wide offset spatula) | Blade, Handle | It carries the dish in the transition. One tool that suits cupcakes, cakes and naan alike. |
| 4 | **Cake stand** | Plate top, Stem, Foot | Porcelain. The top's centre is where the dish sits (put an empty marker object there). |
| 5 | **Cloche** | Dome (glass), Knob | Separate dome and knob so the lift and glint can be animated. Used at the serve. |
| 6 | **Dishes** (now: cupcake, small cake, large cake; then the PRD's five) | Base (liner or sponge), Crumb or top surface | **Not** one model per bake state. One model per dish; raw, pale, golden and dark browning come from a material blend driven by code. Rise and sink come from 2 shape keys (blend shapes). A half-baked dish is the same model with sink and pale browning. |
| 7 | **Decorating items** | Frosting finishes (swirl, rosette; "spread" is generated by code), 7 to 10 toppers per dish (berries, candles, sprinkles as one instanced mesh, herbs and so on), 6 plates | Toppers are small, cheap models and reused across dishes where it makes sense. |

Later: oven skins (a paid cosmetic, PRD MO-2) are new materials on the same oven model. A different oven shape needs the same part names.

### B. Materials, textures and lighting

- **PBR materials** for each model: base colour, roughness, normal, ambient occlusion, plus metallic for steel and emission for the heating elements. Use Blender's Principled BSDF only; it's what USD export understands.
- **Browning:** a set of crust textures (or a colour ramp), from raw to dark, per dish. Code blends between them.
- **Environment lighting:** one warm kitchen HDRI. A CC0 one (for example from Poly Haven) is fine; log it in `LICENSES.md`.
- **Baked lighting** for the static set (counter, wall): bake it in Blender to a texture so the app doesn't calculate it live.
- **Steam, crumbs, sugar sparkle:** small soft-alpha sprite textures (1 to 4 images). The particles themselves are code.

### C. Sound (record or license, all original or licensed)

Everything the transition and decorating need, beyond the existing `ready-chime.wav`:

| Moment | Sounds |
| --- | --- |
| Oven | Door latch and creak (open, close), oven hum (loop), element tick, rack slide |
| Transition | Spatula slide under the dish, soft lift, dish set down on porcelain, a faint glass ring from the cloche |
| Decorating | Frosting squeeze, sprinkle scatter, topper tap, 30 s and 5 s chimes |
| Serve | Cloche lift with a glass ring, serve flourish, camera flash for the share card |
| Room tone | A quiet kitchen ambience loop, very low |

Format: 48 kHz WAV or CAF, short, trimmed, normalised; loops cut at zero crossings. Sounds use the `.ambient` audio session (the silent switch mutes them, CLAUDE.md rule 3).

### D. 2D and marketing (rendered from your Blender scenes)

- **App icon:** render of the oven or the cloche, single subject, all sizes, including the light, dark and tinted variants.
- **Live Activity, Dynamic Island and Watch glyph:** these can't show 3D. A custom SF Symbol (`.svg` from the SF Symbols app) of the oven and cloche silhouettes.
- **App Store:** 6 to 8 screenshots, a 15 to 30 s app preview video, and a still for the share card's backdrop.
- **Recipe-book silhouettes** (PRD CL-1): flat renders of each dish, as dark shapes.

## What stays in code (Swift)

| Area | In code |
| --- | --- |
| Scene and camera | Loading each model, placing it in the slot that fills each half of the screen (`OvenFrame`/`OvenStage`, `CoverStage`), framing per device (the iPhone's top half is nearly square, about 402 × 437 pt; the Duo's halves are landscape, about 669 × 475 and 678 × 466 pt), the camera path of the transition |
| Motion from game state | Door angle (from the hinge or the face-down sensor), rack slide, knob turn, element glow with heat, browning blend from doneness and temperature, rise and sink, steam particles |
| Player-made things | Icing strokes generated along the finger's path, topper placement, scale and rotation, the operation list (stroke, stamp, plate, backdrop, caption) |
| Interface | All text, the timer display on the oven, ring clocks, buttons, the decorating tabs and tray, Live Activity and Watch views, localisation |
| Feel | Sound and haptic timing (Core Haptics patterns as `.ahap` files, written in code), Reduce Motion alternatives, VoiceOver |

## The oven to plating transition (one continuous shot)

**Set:** one counter. The oven sits at the left end, the plating station (cake stand, cloche resting beside it) at the right, about 1.2 to 1.6 m apart. The camera starts framed on the open oven exactly as on the grade screen, so the cut into the transition is invisible.

| Beat | Time | What happens | Sound and haptic |
| --- | --- | --- | --- |
| 1. Settle | 0.0 to 0.3 s | Grade UI fades; camera holds on the open oven, warm glow, steam. | Oven hum fades down |
| 2. Rack out | 0.3 to 0.8 s | The rack glides out toward the viewer. | Rack slide; light haptic tick |
| 3. Lift | 0.8 to 1.3 s | The cake lifter slides under the serving (one cupcake, or the whole cake) and lifts it. | Spatula scrape, soft lift |
| 4. Travel | 1.3 to 2.6 s | The camera dollies right along the counter, keeping the dish centred and slightly ahead (ease in and out, no rotation). The oven drifts out of frame; the stand and cloche come in. | Room tone only |
| 5. Set down | 2.6 to 3.1 s | The dish lowers onto the stand; the lifter slides out and away. | Porcelain tap; one soft haptic |
| 6. Ready | 3.1 to 3.5 s | Light warms on the stand; the decorating tools rise into the bottom half. | Faint glass ring from the cloche |

- **When it plays:** on the Decorate tap only. If the app comes back mid-break, it opens at the station.
- **Skippable:** a tap jumps to beat 6.
- **Reduce Motion:** cross-fade from the oven to the station (about 0.35 s), no camera move.
- **The Duo:**
  - Unfolded, the shot plays in the top half; the bottom half (the door, then the tool tray) never moves.
  - Folded, the cover shows the end frame only.
- **The serve (later):** the same set. The cloche lifts off the counter, arcs over and lowers onto the dish with a glass ring, which is the share card moment.

**How it's built in each pipeline:**

| Pipeline | How |
| --- | --- |
| Live 3D | One RealityKit scene with the set. The camera moves along a path in code. Any dish, browning or topping works automatically. |
| Blender renders | One video per dish and browning state (at least 3 dishes × 4 states = 12 clips, more per new dish), plus separate renders per screen shape. |
| Hybrid | Render only the travel (beat 4) without the dish, and draw the dish live on top. |

## Oven build (scripted Blender, 2026-11-01)

The owner's brief replaces the greybox-by-hand in Step 1. Everything is a re-runnable script, so any change is an edit and a re-run.

| Item | Spec |
| --- | --- |
| Reference | `reference/oven_ref.png` (open, elevated, near-frontal) and `reference/oven_ref_closed.png` (closed, front). Match the design; make it far more realistic. No text, logos or brand marks. |
| Size and axes | Metres, about 0.52 W × 0.33 H × 0.40 D. Camera looks along +Y, oven front on y = 0, Z up. |
| Parts | Separate named objects: `Body`, `Door` (children `DoorGlass`, `DoorHandle`), `ControlPanel` (child `Display`), `Knob1`–`Knob3`, `Rack1` and `Rack2` (two racks at the owner's request, each its own object with its origin on the back edge so code slides it out along -Y for plating), `Tray1` on Rack1 and `Tray2` on Rack2 (children of their racks, so they come out with them), `HeatingElement_Top1/2`, `HeatingElement_Bottom1/2`, `Feet`, empties `CakeSlot_A`–`D` on Tray1 and `CakeSlot_E`–`H` on Tray2, all under one `Oven` root empty. These names replace the `Oven_*` names below for this asset. |
| Door hinge | Origin on the hinge axis. `--hinge bottom` (default): axis along X at the bottom front edge, `rotation_euler.x = +radians(angle)`, 0 closed, 88 flat toward the camera, **up to 180 hanging straight down** to match the Duo's hinge (owner, 2026-11-01). The oven sits at the counter's front edge so the door can swing past flat; the hinge test covers 0, 30, 60, 88, 120, 150 and 180°. `--hinge left`: axis along Z at the left front edge, `rotation_euler.z = -radians(angle)`. |
| Materials | Principled BSDF, **procedural only** (no image textures, no external assets): black enamel, brushed anisotropic steel, smoked double glass, rubber, satin knobs, emissive quartz tubes with matching area lights. Light micro-imperfections, never dirty. (Supersedes "no procedural node textures" below for the pre-rendered oven; a USDZ export would need them baked.) |
| Render | Cycles, AgX, transparent background, RGBA PNG. 32 samples for previews, 256 for finals, OpenImageDenoise, bloom on finals only. |
| Triangles | Unrestricted for pre-rendered art; reported at each stage. |
| Deliverables | `scripts/blender/oven.py` → `build/oven.blend` (+ optional USDZ); `scripts/blender/render.py` → `hero_closed.png`, `hero_open.png` (1600 × 1200), `door_000`–`door_047.png` (equal hinge-angle steps over 0–180°, one camera), `manifest.json`; a comparison sheet against the reference per stage. |

| Stage | Output | Gate |
| --- | --- | --- |
| 1 Blockout | Proportions, part split, pivots; grey clay render; overlay on the reference; hinge test at 0, 30, 60, 88° | Owner approval |
| 2 Detail | Bevels (0.5–2 mm), gasket, hinges, knurled knobs, wire rack, vents, screws; clay render | Owner approval |
| 3 Materials | All materials, neutral studio render | Owner approval |
| 4 Lighting and glow | Final closed and open stills | Owner approval |
| 5 Door frames | 48 frames, manifest, export | Owner approval |

Each stage is committed on its own (scripts and renders only).

Stage 1 note: height is 0.35 m, not the brief's 0.33, because at 0.33 the front read 1.58:1 against the reference's 1.39:1; at 0.35 the perspective front matches (1.40). Feet are 32 mm so the open door's handle clears the floor (13 mm at 88°).

Stage 4 note: the racks sit at 105 and 200 mm so a cupcake on either tray has headroom (checked by `render.py`, with a slide-out clearance check through the gasket). Each tube carries a thin warm area light (`*_Light`) so its glow reaches the racks and walls; `materials.set_heat(0..1)` drives tubes and lights together.

Stage 5 note: `scripts/blender/frames.py` renders `build/renders/stage5/door/door_000`–`047.png` (1000 × 1200, transparent, heat on, one fixed near-level camera; frame *i* is at 180 × *i* / 47 degrees) and `manifest.json` with each frame's angle and the pixel positions of the hinge axis and the body front, so the app can map the hinge angle to a frame and line it up with `OvenStage`. Studio softboxes are light-linked off the door glass in these frames (otherwise the key light's edge flashes across the hanging door around 145–160°). `build/oven.usdz` holds only the `Oven` hierarchy, Y-up, for Reality Composer Pro and Quick Look.

## Blender export spec (for the oven now, and every later asset)

- **Scale:** real-world metres (a countertop oven is about 0.50 × 0.32 × 0.40 m), with scale applied.
- **Origin:** bottom centre of the object on the floor plane. Each moving part's origin sits on its pivot: the door on the hinge line, the knobs at their centres, the rack at its back edge.
- **Names:** `Oven_Body`, `Oven_Door`, `Oven_DoorGlass`, `Oven_Handle`, `Oven_Rack`, `Oven_ElementTop`, `Oven_ElementBottom`, `Oven_Display`, `Oven_Knob1`… No spaces. Code finds the parts by these names.
- **Modelling:**
  - Bevels applied, transforms applied.
  - No n-gons on curved surfaces.
  - Normals facing out.
  - Hidden faces deleted.
- **Budget:** oven 30k to 60k triangles; small props under 5k; dishes 10k to 20k.
- **Textures:** 2048 px maximum for hero assets and 1024 px for props, PNG or JPG. Total app download for all art under about 150 MB.
- **Materials:**
  - Principled BSDF only, no procedural node textures (bake them to images).
  - The heating elements get an emission material; the glass gets transmission.
- **No baked text and no baked animation** on parts that code moves.
- **Export:**
  1. Export from Blender as USD (`.usdc`).
  2. Open it in Reality Composer Pro (it comes with Xcode) to check materials and pivots.
  3. Save it as `.usdz`.
  4. Check it in Quick Look on an iPhone.
- **Keep the `.blend` source files** (in Git LFS or a separate drive), not only the exports.
- **Framing check:** the door front reads well at about 1.5:1 (today's door slot is 520 × 348 pt) and cropped close on the nearly square iPhone half.

## Still to decide

1. **Live 3D vs Blender renders vs hybrid:** after the Step 1 spike. This choice decides whether you ever animate in Blender (renders) or only model (live 3D).
2. **Decorating view:**
   - Decorate on the 3D dish from a three-quarter view, which looks best but is harder to build.
   - Or switch to a top-down view of the dish for decorating, which is easier and matches the "normalised to the dish square" operation list in the handoff.
3. **Hands or tools only:** tools only is recommended (hands need rigging and turn uncanny fast).
4. **Who makes assets 3 to 8:** you, a freelancer or bought, especially the food, which is the hardest thing to make look tasty.
5. **Dish lineup:** the app now bakes cupcakes, a small cake and a large cake by length; the PRD lists five dishes (cupcakes, naan, chocolate drip cake, cinnamon rolls, biryani). Which set gets 3D first?
6. **Framework rule:** CLAUDE.md's list of allowed Apple frameworks doesn't name RealityKit yet. It's Apple's own, so it fits "Apple frameworks only", but it needs a DECISIONS row if live 3D wins.
